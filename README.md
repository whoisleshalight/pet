# Portfolio

React + TypeScript + Vite. React Router відповідає за сторінки, GSAP — за анімацію спільного хедера.

## Запуск

```sh
npm install
npm run dev
npm run build
npm run lint
```

У PowerShell, якщо запуск `npm.ps1` заборонений політикою Windows, використовуй `npm.cmd` замість `npm`.

## Структура

```text
src/
  app/
    layouts/site/
      SiteLayout.tsx            Хедер, main, Outlet і відновлення прокрутки
      SiteErrorLayout.tsx       Оболонка для помилок завантаження
      header/                   Розмітка, анімація та налаштування хедера
      scroll/                   ScrollSmoother та його життєвий цикл
    router/applicationRouter.ts Маршрути й відкладене завантаження сторінок
    router/routePaths.ts         Адреси для посилань і маршрутів
  components/
    error-screen/               Спільний вигляд 404 та помилок маршрутів
    scrollbar/                  Динамічна шкала прокрутки, її логіка та налаштування
  config/portfolio.ts           Ім’я, опис, статус доступності та email
  lib/animation.ts              Реєстрація плагінів GSAP
  lib/scroll.ts                 Повернення нагору через ScrollSmoother або звичайну прокрутку
  pages/
    home/                       Головна сторінка
    about/                      Про мене
    contact/                    Контакти
    not-found/                  Невідома адреса
    route-error/                Помилки завантаження сторінок
  styles/
    index.scss                  Єдиний вхідний файл стилів
    _variables.scss             Змінні Sass: кольори, відступи, брейкпойнти
    _base.scss                  Шрифти, базові правила й типографіка
    _mixins.scss                Спільні правила типографіки
```

## Маршрути

- `/` — головна сторінка.
- `/about` — про мене.
- `/contact` — контакти.
- Невідомі адреси показують сторінку 404 зі спільним хедером.

Сторінки завантажуються окремими JavaScript-файлами. Спільний layout не перемонтовується під час переходів. Для внутрішніх переходів використовуються `Link` і `NavLink`.

### Як додати сторінку

1. Створи папку у `src/pages` і компонент із повною назвою, наприклад `ProjectsPage.tsx`.
2. Додай адресу `projects: '/projects'` у `routePaths.ts`.
3. Додай дочірній маршрут у `applicationRouter.ts`: `path`, `handle.title` і `lazy` за прикладом About.
4. За потреби додай пункт у `navigationItems` у `app/layouts/site/header/Header.tsx`.

Для вкладених розділів додавай `children` до відповідного маршруту й `Outlet` до його layout. Базовий layout, 404 та обробник помилок уже налаштовані.

## Вміст і вигляд

`SiteLayout` рендерить хедер і головний контент. Сторінки містять лише свій контент. Режим хедера задається через `handle.headerVariant` у маршруті: `expanded` для головної, `compact` за замовчуванням для решти. Сторінка помилки також отримує хедер від свого `SiteErrorLayout`.

`Header` містить ім’я, опис, статус доступності та навігацію. `HeaderIntroduction` відповідає за великий вступ, `HeaderBrand` — за компактний бренд і його маски літер, а `useHeaderAnimation` — за анімацію. Тексти змінюються в `src/config/portfolio.ts`.

Елементи хедера розміщені через CSS Grid і Flexbox. Компактний бренд закріплений у верхній лівій комірці; під час прокрутки його літери окремо піднімаються з масок, а меню рухається до того самого рядка. Анімація змінює лише трансформації, прозорість і видимість; розміри сітки залишаються сталими. Зсув меню обчислюється з поточних розмірів елементів і перераховується при `ScrollTrigger.refresh()`. На мобільних хедер займає місце у звичайному потоці документа.

Шрифти зберігаються локально в `public/fonts`; під час роботи сайт не звертається до референсу. На екранах до 1024px та при `prefers-reduced-motion: reduce` анімація прокрутки вимкнена. GSAP прибирає анімації та ScrollTrigger при виході зі сторінки.

`main` містить лише контент сторінки. Layout не вимірює його висоту та не додає автоматичних відступів. Налаштування переходу хедера лежать у `app/layouts/site/header/headerAnimationSettings.ts`: `introScrollDistance` — 800px, `introScrollSmoothingDuration` — 1s. Відстань анімації не залежить від висоти сторінки. У `HomePage` є дві порожні секції висотою `150vh` кожна.

Компонентні стилі зберігаються в `.module.scss` поруч із `.tsx` та підключаються через `import styles`. `src/styles` містить лише глобальні стилі, змінні `$` та спільні mixins. Глобальний `styles/index.scss` підключений у `main.tsx`; `textLink` залишається спільним глобальним стилем посилань. Локальні CSS-класи — у camelCase.

Правила анімацій визначені в `AGENTS.md`. Складна логіка хедера, плавної прокрутки та скролбара винесена в сусідні папки `hooks/`; компоненти експортуються через `index.ts`. GSAP реєструється в `lib/animation.ts`, а ініціалізується в `useGSAP()` з областю компонента. Окремі елементи передаються через refs, групи — через локальні селектори SCSS Modules. Взаємодії, що запускають GSAP, обгорнуті в `contextSafe()`. Контексти, медіазапити, ticker, спостерігачі та слухачі очищаються при демонтуванні або зміні залежностей. Це відповідає [документації GSAP для React](https://gsap.com/resources/React/).

## Плавна прокрутка

`SmoothScroll` відповідає лише за прокрутку: `smoothScrollWrapper` — контейнер, а `main` використовується як `content` ScrollSmoother. Службові трансформації GSAP застосовуються до `main`. На екранах від 1025px прокрутка згладжується; інтенсивність задається параметром `smooth` у `useSmoothScroll`. На мобільних та при `prefers-reduced-motion: reduce` працює звичайна прокрутка.

Увесь хедер розташований поза контейнером ScrollSmoother та залишається прив’язаним до екрана під час анімації. Один екземпляр ScrollSmoother працює протягом життя layout. Після зміни маршруту оновлюються розміри та позиція з `ScrollRestoration`; при демонтуванні або вимкненні згладжування екземпляр очищається.

Для повернення нагору використовуй `scrollToTop` із `src/lib/scroll.ts`.

## Скролбар

`components/scrollbar/Scrollbar.tsx` — окремий компонент зі шкалою рисок за мотивами `home--rightnav` на [сайті Eric Huguenin](https://erichuguenin.com/en/). Він підключений один раз у `SiteLayout`, поза трансформованим контейнером ScrollSmoother. `hooks/useScrollbar.ts` відповідає за вимірювання, позицію та взаємодію, `Scrollbar.module.scss` — за вигляд.

Кількість рисок обчислюється з фактичної висоти документа. `pixelsPerLine` у `scrollbarSettings.ts` задає кількість пікселів висоти на одну риску. Шкала займає не більше `70svh`; кількість рисок обмежується доступною висотою та їхнім кроком зі SCSS. На сторінках без прокрутки компонент прихований.

`ResizeObserver` і подія `ScrollTrigger.refresh` оновлюють шкалу після зміни контенту, завантаження зображень, зміни розміру вікна та переходів між сторінками. Активна риска слідує за реальною позицією ScrollSmoother, а на мобільних — за звичайною прокруткою. Оновлення позиції не спричиняє React-рендер на кожному кадрі.

Натискання на шкалу плавно прокручує до вибраної позиції; перетягування мишею або дотиком слідує за вказівником без затримки. `dragThreshold` задає мінімальний рух для початку перетягування, щоб невелике тремтіння не скасовувало плавний перехід. Працюють клавіші `↑`, `↓`, `PageUp`, `PageDown`, `Home`, `End`; `keyboardStep` задає крок стрілок. `prefers-reduced-motion` вимикає плавні переходи. Для програмної прокрутки на задану позицію використовуй `scrollToPosition` із `src/lib/scroll.ts`.

## Розміщення на хостингу

Для `createBrowserRouter` сервер має повертати `index.html` для адрес сторінок, які не відповідають наявним файлам. Це дозволить відкривати `/about` і `/contact` напряму та оновлювати їх. Сервер Vite вже підтримує таку поведінку.

Наприклад, для Nginx:

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```
